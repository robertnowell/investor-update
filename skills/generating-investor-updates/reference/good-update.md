# What a good investor update is — the opinionated base

Grounded in widely-cited guidance (Lenny Rachitsky, YC/Aaron Harris, 500 Global, Founder
Institute, Visible.vc, Uncork, Earnest Capital) and in real founder updates. This is the spine;
it does not change between months.

## OVERRIDING RULE — headline-only, 30-second grok
The reader has ~30 seconds. The update is **basically bold one-line headlines + one metrics row**.
Each section is one scannable line (a headline + the number), not a paragraph. The compiled
digest is INTERNAL fuel — only the crystallized headlines ship. Calibration:
- "tl;dr — 31% ARR growth, feature X launched today."
- "Crossed $2M ARR (2 mo ahead of plan). Signed 3 enterprise logos. Eng at 95% — hiring."

## Section set (stable every month)
```
Subject: {Company} — {Month YYYY}: ${cash} cash · {runway}mo runway · {MRR} MRR ({±}% MoM)

1. TL;DR              2–3 bullets: good month? why? headline number.
2. Metrics row        FIXED schema, repeated identically: Cash · Burn · Runway ·
                      Revenue/MRR (±% MoM) · Customers (±% MoM) · 1 usage metric.
3. Highlights         Wins + shipped + revenue generated (crystallized from the digest).
4. Lowlights / risks  Honest. What's not working.
5. This month's focus Targets; grade last month's.
6. Asks               1–3 SPECIFIC, network-leveraging (named hire + link, named intro, fundraise).
7. Spotlight (opt)    A personal note + CTA.
```
Order is a defensible default (TL;DR first, cash early). The consensus is on the SET + cash-first
emphasis, not one fixed sequence — but pick one and keep it stable.

## One-page checklist — a strong update MUST have
- [ ] Cash + burn + runway up front (cash is the single most-expected figure)
- [ ] Revenue/MRR with a MoM delta
- [ ] The SAME metric names/definitions as last month (changing them breaks trust)
- [ ] At least one genuine win AND one honest lowlight
- [ ] 1–3 specific asks (not "let us know if you can help")
- [ ] Default Alive / Dead stated (computed — see below)
- [ ] ≤5-minute read; headline-only
- [ ] Sent to the INVESTOR list only — never customer/campaign lists

## Default Alive / Dead is COMPUTED, never assumed
NOT a function of runway length. (Paul Graham:) you are **default alive** only if current revenue
*and its growth rate* reach profitability (revenue ≥ burn) before cash runs out, WITHOUT raising
again. If revenue is far below burn and not growing fast enough to cross it within runway →
**Default Dead**, which is normal/expected pre-seed. Do the arithmetic (break-even revenue = burn;
can current growth get there before months-of-runway?). If it's not clearly alive, write
**Default Dead** or omit the status — never stamp "Default Alive" to look good.

## Hard rules
- Never invent numbers, offers, prices, or milestones. Every figure traces to the founder's
  entered financials, the compiled digest, or an explicit prior update. Mark unknowns `[confirm]`.
- MoM deltas compute against the most-recent prior update (pulled via the Kopi MCP).
